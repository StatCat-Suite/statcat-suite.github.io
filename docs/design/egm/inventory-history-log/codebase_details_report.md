## Blockers

### B1. A restore reuses `seq`, so `history/<seq>.json` collides with lost history (lines 81, 87, 126-128, 141-147, 234)
`next_root` numbers `previous.seq + 1` (sdmxlib `_rules.py:506`); `conformance.py:110-115` defines `restore_to` and `restore_with_new_epoch` as "Lose every version after `seq`"; the statcatlib RFC (`products-editions-inventory.md:638-639`) says "the next write reuses seq numbers from the lost history". The new writer finds the lost version's record, sees a different `root_sha256`, and replaces it, destroying the audit record of exactly the lost versions. `restore_to` keeps the epoch (`conformance.py:110-111`), so line 127's null-at-epoch-change rule does not fire and the chain breaks with no explanation.
**Fix:** key records by epoch and root hash (`history/<restore_epoch>/<seq>.<root_sha256>.json`, zero-padded like `root_path`, `_format.py:250`); never replace or delete a record except by compaction; add a conformance case (restore, write the reused seq, the old record survives).

### B2. Orphan replacement is unsafe, and no writer has ETags or conditional replace (lines 141-147, 233, 272-273)
The race in `design_storage_report.md` B1 holds. `next_root` stamps `created_at=now` (`_rules.py:515`) and `try_commit` passes `datetime.now(UTC)` and a fresh `Event` (statcatlib `inventory.py:417-428`), so the reuse branch never fires. `InventoryWriter(root: Path)` is local-disk only: `sdmxlib.storage.create_exclusive` is staged file + fsync + `os.link` (`storage/_files.py:89-116`); `CURRENT` uses `os.replace` (`inventory.py:353-363`). Neither src tree uses `obstore`, ETags or If-Match; the blob path is Phase 4 (`phase-2a-catalog-editions.md:155-157`).
**Fix:** create-only records named by content; the valid record carries its root's hash; losers are orphans `verify-catalog` lists and expiry deletes. Needs only `create_exclusive` and `If-None-Match: *` (§6.6 line 483).

### B3. Expiry leaves seq gaps, and the reader returns a stale version when it meets one (lines 37-38, 64, 151-158)
`_reader.py:119-148`: on a bad `CURRENT` root it walks back `seq-1, seq-2, …` to the floor (lines 132-136), then probes forward to the first absent seq (lines 140-144); with no `CURRENT` it starts at 0. With checkpoints between expired roots: a fresh reader with `CURRENT` missing (§10.3 line 718 copies `CURRENT` last) reads version 1, which line 151 keeps, probes 2, finds it expired, and returns version 1 as newest. With `CURRENT` corrupt and the K-1 roots below it bad, it walks past the gap to a month-old checkpoint. Non-goal line 64 holds only if readers never see a gap; §6.6 step 3 (line 492) assumes none.
**Fix:** a §6.6 rule and reader change: expiry deletes only roots below the oldest of the newest K, K >= 2; the fallback walks back at most K versions; a missing `CURRENT` on a catalog with retained checkpoints is an error, never a probe from 1. Conformance cases for both. sdmxlib-rest depends on sdmxlib's reader (`tests/test_inventory_describe.py`), so the contract names the sdmxlib release that carries the change.

## Majors

- **M1. Goal 5 is false as worded** (lines 59-60, 160-163, 207). §10.1 gives the release job write only (line 700), GC read (line 701). With delete, the release identity can delete and recreate any root or record. "Only write path" holds on the server (§10.1 line 706, §11.2 line 738); locally `InventoryWriter` writes from `WorkingCopy.seal`, `settle_journal` and `CatalogAdmin` (`store/EGM.md:353`). **Fix:** reword Goal 5; add a `history/` column.
- **M2. P7 is quoted without "until Phase 4"** (lines 34-35, 44-46, 163, 216-217). `phase-2a-catalog-editions.md:274`: "Roots, leaves and tombstones are kept until Phase 4." Its Non-Goals (lines 168-170) and Future Improvements (lines 875-876) assign root and leaf deletion to the server GC. `admin.py:538` confirms prune deletes no root or leaf today. **Fix:** quote P7 fully; say this design moves expiry from the planned server GC to the release job; mark the Phase 2a entry superseded.
- **M3. §11.4 and §11.6 constraints missing or misread** (lines 44-46, 154-157). §11.6 (lines 766-770) quoted: "backup retention ≤ the `data/` GC window ≤ the tombstone window (§10.3); the longest pod poll interval plus fetch time < Inventory version retention; objects reachable from the newest K roots are never deleted." §11.4 (line 756) has GC read back through its window. Line 155's reason ("so a whole-catalog restore finds its roots") does not match §10.3: a restore brings roots from the backup, and a restored version "is never made current" (line 718). **Fix:** W >= the `data/` GC window in §11.6, or amend §11.4 so GC reads only the newest root's leaves and `retired` list; state the pod-poll inequality; set K; drop or correct the restore reason.
- **M4. Backups, layout and namespace text omit `history/`** (lines 77-83, 253-254). §10.3 line 718; §4.1 (lines 107-123); hub `docs/architecture.md:41-42`; Phase 2a "statcatlib adds no file to it" (`phase-2a-catalog-editions.md:355`). **Fix:** add §4.1 and the hub page to the Handoff; copy `history/` after roots and before `CURRENT`; pad to 12 digits (`_format.py:246-250`).
- **M5. No RFC 8785 implementation exists; every digest hashes bytes as written** (lines 116, 124-128, 205). `root_sha256`, `leaf_sha256` and `CURRENT.root_sha256` are `sha256_hex` over msgspec indented `encode()` output (`_format.py:258-265`; `inventory.py:360, 414`). No pyproject depends on an RFC 8785 library. `sdmxlib.edition.canonical_json` (`edition/_canonical.py:56`) is sorted compact JSON for attrs models with its own datetime and float rules, versioned by `CANONICAL_FORM`; it is not RFC 8785 (Python code-point key order differs from UTF-16 code-unit order; number formatting differs). **Fix:** add and name an RFC 8785 dependency, or hash the record's exact stored bytes (compact msgspec, no indent), with segment lines holding the same bytes; define the bytes behind `extensions_sha256`.
- **M6. "Previous" is ambiguous** (lines 98, 121-122, 126, 189). `previous_inventory` is "Usually `seq - 1`; a correction builds from an older, known-good one" (`_format.py:138-140`; `next_root(built_from=)`, `_rules.py:495-511`). **Fix:** `prev_sha256` chains to seq-1 in the same epoch; `changes` diffs against `previous_inventory`; PROV revision uses `previous_inventory`; a `correct` built from an expired version is refused.
- **M7. The example breaks the schema and transition rules** (lines 102, 110, 115). `release_at` is None outside `embargoed` and `validate_leaf` refuses it (`_format.py:204-205, 401-403`; spec line 378). The tombstone in a `release` version conflicts with §6.4 line 444 and `CatalogAdmin.prune`, which writes `kind: retire` (`admin.py:525-528`). The other two transitions are legal (§6.4 lines 437, 440). **Fix:** rename and define the release-time field; move the tombstone to a `retire` record; `retired` = tombstones added; add `unretired`.
- **M8. PROV-O terms missing or misplaced** (lines 185-192, 208, 269-271). No `stc:` prefix anywhere in the four repos; statcatlib "adopts the concepts without the RDF runtime" (statcatlib `CLAUDE.md:796`). `hadRole` needs a qualified association. Rollback re-enters `live` (§6.4 line 442), against generation-uniqueness. `reinstate` (line 443) contradicts invalidating the edition. No `prov:Attribute` class. PREMIS's element is `linkingAgentIdentifier`. statcatlib's `lineage` maps more than `wasDerivedFrom`: `docs/tutorial.md:560-569` maps `revision_of` and `replaces` to `wasRevisionOf` and `uses_classification` to `used`; the table has `activity_label`, `activity_type`, `agent_id`, `timestamp` (`schema.py:335-347`); its DCAT side uses `dct:provenance` (`model/quality.py:27`). **Fix:** see `prov_o_report.md`; reuse `revision_of`'s mapping for an edition's `previous`.
- **M9. Embargo boundary not stated for `history/` or the export** (lines 104-110, 180-181, 240-242). §10.1 line 710. **Fix:** same readers as `inventory/`; export inside the boundary or live-only.
- **M10. The conformance suite needs unnamed protocol changes** (lines 240-243, 256-257). `Backend` (`conformance.py:75-116`) has no record or expiry hook. Three implementations change: statcatlib `tests/test_inventory_conformance.py`, sdmxlib `tests/support/inventory.py`, the Delta prototype `tests/support/inventory_backends.py` (`inventory/EGM.md:74-80`). Delta already gives `commitInfo`, checkpoints and log retention, a reuse point for Question 1. **Fix:** list the new methods, the Delta backend's support, and the three files.
- **M11. Expiry races writers that reuse a leaf** (lines 156-163, 232). `_write_leaf` returns early (`inventory.py:339-344`); `try_commit` reuses base leaf refs (`inventory.py:412-416`); `correct` reuses an old version's leaves; `MAX_RACES` exists because writers race (`inventory.py:88`). **Fix:** expiry holds the writer's exclusion; recompute reachability from a re-read head after deleting roots and before deleting leaves.
- **M12. Commands cited as existing are unbuilt** (lines 38-40, 147, 172-176, 232-233). `rebuild-inventory` and `--find-newest-consistent` exist only in prose (spec §6.7 line 514; RFC `products-editions-inventory.md:643`; Phase 2a Non-Goals lines 173-180), planned for Phase 9 (sdmxlib `docs/design/egm/sharded-catalog-replan/README.md:31`). §10.3 says `verify-catalog` "walks the newest root"; the built `verify_catalog` reads only the newest valid root (statcatlib `diagnostics.py:303-353`). **Fix:** cite correctly; say the scan cost is future cost; every record check is new work.

## Nits

- **N1** (lines 218-223, 267-268). Quote §6.6 line 499 exactly. RFC decision 31 (`products-editions-inventory.md:898-899`) is the conformance suite run against a Delta prototype; the escape route itself is RFC §3 (lines 161-164).
- **N2** (lines 96-102, 117). Rename `prev_sha256` to `previous_record_sha256` to match `previous_inventory` and `LeafEntry.previous`. Add `catalog_id` (`_format.py:59-71`), which `CatalogAdmin.export` keeps (spec line 333). The other names match the schemas exactly: `format_version`, `seq`, `previous_inventory`, `restore_epoch`, `created_at`, `producer`, `event`, `embargo`, `root_sha256` (as in `Current`), `leaf_sha256` (as in `LeafRef`), `retired` (as in `Tombstone`).
- **N3** (lines 32, 124-125). "fold" is no `event.kind`: it is the release job's fold of `pending/` (§11.2 line 736) or `fold_overlays`. `describe` is a kind (`_format.py:41-43`) and `CatalogAdmin.describe` (`admin.py:505-516`). A Phase 7 search version lives in `extensions.statcat` (§12 line 780) with no kind, and `describe` means the description "and nothing else"; Phase 7 needs a new kind.
- **N4** (lines 30-31). With indent 2 a `products` entry is about 220-230 bytes. The plan has about 6,550 products covering 7,000 tables (plan line 94). Say "up to 7,000" and that the size is an estimate.
